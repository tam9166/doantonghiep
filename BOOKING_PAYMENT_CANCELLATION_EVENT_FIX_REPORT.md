## 2. Booking preorder pagination root cause

Reservation preorder previously rendered one button for every page. With a large menu, the pagination became too wide and hurt the booking step layout.

Fix: Reservation.vue now uses compact page buttons with ellipsis through `preorderPageButtons`.

## 3. Menu picker width/layout root cause

The preorder picker had grid/full-width leakage where filters, summary, menu grid, and selected dishes competed in the same grid area.

Fix: Reservation.vue now separates the main picker column from the selected-dishes panel using `menu-picker-main` and `selected-dishes-panel`.

## 4. Selected dishes jump root cause

The selected dishes block was conditionally rendered only after items existed, so the right-side panel appeared/disappeared and caused visual jumping.

Fix: the selected-dishes panel remains mounted while preorder is enabled and shows an empty state when no dish has been selected.

## 5. Unavailable dish handling

Preorder menu API now returns active dishes even when unavailable or sold out, allowing the frontend to display them disabled instead of hiding them silently.

Reservation.vue and EventBooking.vue now sort available dishes first, show unavailable labels, and block add/quantity mutation for unavailable items.

## 6. Backend availability revalidation

ReservationService now revalidates each preorder item against product status, product availability, and computed available quantity before saving reservation/event booking preorders.

This prevents stale frontend data from creating invalid preorder items.

## 7. QR status root cause

QR actions previously refreshed status without clear customer-facing state feedback, making paid/expired/pending outcomes unclear.

Fix: Reservation.vue now shows `qrStatusMessage` for refresh/regenerate outcomes.

## 8. QR regeneration behavior

QR regeneration keeps the existing backend payment flow and updates the UI with a fresh success message after the new QR response is returned.

No fake payment flow was added.

## 9. Unpaid booking lookup fix

ReservationLookup.vue now supports cancellation preview even when no refund is expected, instead of assuming every valid lookup must have a paid deposit/refund amount.

## 10. Cancellation/refund implementation

Cancellation preview now uses backend-calculated fields:

- orderTotalAmount
- paidDepositAmount
- penaltyAmount
- refundRate
- expectedRefundAmount
- hoursBeforeReservation
- policyApplied

Frontend no longer calculates or hardcodes the refund policy.

## 11. Exact refund formulas

Backend policy:

- At least 24 hours before reservation: refund 100% of actually paid amount.
- From 12 hours to under 24 hours: cancellation penalty equals 50% of order total; refund is `max(paidAmount - penalty, 0)` and never exceeds paid amount.
- Under 12 hours: keep current no-refund policy.

## 12. Policy currently used for under 12h

Under 12 hours before reservation, the existing policy remains unchanged: no refund.

## 13. Event Hall menu picker redesign

EventBooking.vue now has a grid menu picker with search, category filter, compact pagination, selected-dishes panel, quantity controls, unavailable handling, and backend-compatible preorder payload.
